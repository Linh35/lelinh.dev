Shipped

Running in production.

  • When.

    A private period tracker that lives in the calendar you already check — Google, Notion, or CalDAV — not one more app to open. Log the day a period starts; it learns your cycle and drops each predicted phase onto your calendar. The calendar is the only datastore: no cycle data is held on our side, which decided every architectural call that followed. TypeScript throughout, server-rendered with Preact — React's component model and hooks at a fraction of the bytes, which is what a server-rendered page wants. Co-created with Anna, and run end to end.

    getwhen.net · live · €4/mo after a 14-day trial

  • Self-hosted stack

    Twenty services on my own hardware: photos, files, music, documents, media, search. Rootless Podman under Caddy, reached from outside the house over a Cloudflare Zero Trust tunnel rather than a public hostname, with restic backups. Replaces a stack of subscriptions I'd rather not pay for.

    podman · caddy · zero trust · restic
In progress

A real-time 3D editor and runtime, in Zig.

An editor and a runtime over a Vulkan renderer, written in Zig. You compose a scene visually — entities, components, an inspector, lights, meshes, physics and UI — and it serialises to a .zon file. A separate generic runtime deserialises that file and drives it with zero scene-specific code, which is the point: the data describes the application, and the runtime stays general.

Three executables over one shared engine module and one entity-component-system world: the editor, the generic runtime, and a hand-wired scene that exercises the render and interaction paths an empty scene would hide. It is the closest thing I have to a hard real-time problem right now — a frame budget, a GPU, and a compiler that all have to be satisfied at once. It's also the codebase my model fleet works against, so the verification runs against a real compiler rather than a benchmark.

Private while it's in progress.

Workshop

Small tools, written to be read.

  • baker

    Single-binary static site bundler and HTTP server in Zig. Brotli + gzip, ETags, 304s, hot reload via SIGHUP. Bakes a site into one .bin file, then serves it.

    Zig

  • zremdic

    A latency-focused key-value cache over UDP, in Zig. One datagram per lookup, a sharded store with a worker per core, atomic ops with exactly-once semantics over an unreliable transport, TTLs and LRU eviction. ~210k ops/sec at ~19μs on loopback. A cache, not a database: values live in memory only.

    Zig · ~210k ops/sec

  • zhecs

    An entity component system in Zig, small enough to read in an afternoon. Plain Zig types as components, no registration; matching entities stored together in contiguous columns. Systems run in ordered phases. A million entities stepped in ~19 ms per chunk.

    Zig · 1M entities

  • swr

    A SharedWorker HTML renderer on top of ssw. Views are functions returning HTML strings; the render runs once in the worker and broadcasts to every tab, skipping identical output so no tab repaints for nothing. ~65 integration tests.

    TypeScript

  • ssw

    Multi-tab state, no ceremony. SharedWorker as the single source of truth, optimistic per-tab mirror, batched ack protocol. ~3.5 KB gzipped, tested against real MessageChannels.

    TypeScript · 3.5 KB

  • wiki-art-downloader

    Bulk-downloads an artist's catalogue from WikiArt as JPGs. Node 18+, zero deps. Walks the eight CDN shards in parallel, with dry-run and resume-by-skip.

    Node · zero deps

How the site is built.

Vanilla HTML, CSS and ES modules. No framework, no build step, no bundler, no runtime dependencies. Every JS and CSS file is under 150 lines and opens with a header saying what it does and what it must not do; a script in the repo enforces both mechanically.

Two reads share one set of pages. Brief is the short version — claims, numbers, and how to reach me, in one screen. Deep restores the architecture and the tradeoffs. Both are in the HTML at once, so with JavaScript disabled you simply get all of it.

assets/
├── kernel/    bus, router, mode
├── modes/     brief/ · deep/ renderers
└── features/  indicator, shortcuts, hints
